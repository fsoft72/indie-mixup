# Multi Tier specs

I need to create a new module for the LiWE ecosystem to handle Multi-Tier "sub"-domains.
We'll use the `domain` field with some modifications to handle subdomains.

A domain is identified by its `code` field. The new subdomains are created by prepending the previous domain with ":", eg. parent:new_domain

A code is generated using this formula:

```javascript
const start_time = new Date( '2025-10-09 11:00:00' ).getTime();
const dom = ( ( new Date().getTime() - start_time ) / 1000 / 60 ).toString( 36 );
```

A domain is generated by appending new domains to the parent domain, separated by ":", eg. `parent:new_domain1:new_domain2`

User can have different roles:

- `admin` will be able to create domains and assign the `multi-tier` role to users. He can also define the number of tiers allowed for a specific domain
- `multi-tier` user will be able to create subdomains under their domain and assign the `user` or `multi-tier` role to other users. Also multi-tier users can create subdomains up to the defined number of tiers.
- `user` will not be able to create subdomains

## Specs

- Each domain can have a defined number of tiers, which will limit the number of subdomains that can be created under it.
- Each subdomain can have its number of tiers defined, allowing for a hierarchical structure of domains.
- A subdomain can only be created by a user with the `multi-tier` role in the parent domain.
- A user with the `multi-tier` role can create subdomains up to the defined number of tiers.
  So for eg. Domain 'A' has 5 tiers, subdomain 'A:B' has 3 tiers, subdomain 'A:C' can only have 2 tiers (5-3 from A:B).
  Another eg. Domain 'A' has 5 tiers, subdomain 'A:B' has 2 tiers, subdomain 'A:B:C' has 2 tiers, subdomain 'A:C' can only have 1 tier (5-2-2 from A:B:C).
- Each subdomain can have its own set of users and roles, independent of the parent domain.
- When a subdomain is created, also a new user with `multi-tier` role is created for that subdomain. The username will be the full domain code + "-admin", eg. `A:B-admin`, also email will be `A:B-admin@example.com`, with a random password.

- A user with the `multi-tier` role can assign the `user` or `multi-tier` role to other users within their domain or subdomain.
- A user with the `multi-tier` role can change/reassign user roles within their domain or subdomain, but cannot assign the `admin` role.
- Also the first code is generated using the formula above.
- When creating a subdomain, the final code is generated by appending the new code to the parent domain, separated by ":", eg. `parent:new_code`.
  eg. "A", subdomain created "B" => "A:B"
  "A:B", subdomain created "C" => "A:B:C"
  "A", subdomain created "D" => "A:D"
- A user is locked to a specific domain or subdomain, and cannot access or manage other domains or subdomains unless assigned the appropriate role.
- The system should validate the number of tiers when creating a subdomain to ensure it does not exceed the allowed limit.
- The system should provide an interface for users with the `multi-tier` role to manage their subdomains and user roles.
- The number of tiers for a domain or subdomain can be updated by an `admin` user or a `multi-tier` user if he owns the original subdomain, but cannot be increased beyond the original limit set for the parent domain.
- When a subdomain is deleted, all its subdomains and users should also be deleted.
- `total_max_tiers` can be modified by an `admin` user or a `multi-tier` user if he owns the original subdomain, but cannot be increased beyond the original limit set for the parent domain. If he tries to reduce it below the current number of tiers used, the operation should fail.
- If a domain is deleted, all its subdomains and users should also be deleted.
- `tiers_allocated` field is automatically updated when a new subdomain is created or deleted, and it should be at least equal to 1.

### Auto provisioned admin users

- Password for `${new_domain_code}-admin` users are auto generated by using the `mkid()` function, then hashed as md5. Nobody will be able to login with that password, but only the `admin` user can reset it.
- Auto generated admin users are enabled by default
- Default language for auto generated admin users is the same as the current user creating the subdomain.
- The current `system_domain_get_by_session` function should return the user's exact domain.
- Permissions like `system.domain` DO NOT supersede `domain.multi-tier.create_sub`, only `system.admin` can create everything as usual.
- Existing domains in the system: should automatically become root domains with default `total_max_tiers` set to 1.
